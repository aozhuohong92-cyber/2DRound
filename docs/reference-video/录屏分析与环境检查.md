## 恢复路线

优先验证原 Cocos2d-x/Lua 运行路线：还原资源路径 → 显示原 CSB 界面 → 播放原 Spine 角色 → 接入本地状态 → 引导到第一场战斗。若采用 Creator，则属于迁移开发，须重建 Lua 逻辑、CSB 节点及旧 Spine 兼容层，不能把升级编辑器当作恢复原工程。

保留原素材和布局作为对照基线。先固定原包版本；录屏可能含热更新内容，因此发现差异时分别记录包内实现与录屏表现。不要为通过截图对比而用整张截图替代交互界面。

离线数据层在客户端内提供角色、背包、队伍、关卡、引导进度、召唤与奖励状态，并本地持久化。无需部署服务端，但原网络消息驱动的状态仍要补齐。战斗控制器可见 20027 开战初始化、20002 回合、20004 技能数据、20006 结算，以及客户端 20005 演出完成通知；这是消息角色分析，不代表字段与完整计算公式已恢复。

先用固定战报验证动作播放、镜头、血条与结算，再做独立本地战斗计算。固定战报只能验收该场演出，不能声称已恢复所有战斗规则。召唤同理，确定性样例可核对翻卡表现，录屏无法证明原随机概率。

## 具体验收顺序

1. 工具链：原生空工程构建成功，目标 Android 设备运行；保留构建日志。
2. 资源：主城/召唤/战斗界面可加载，一个角色待机、攻击、受击完整播放。
3. 引导：命名→基础召唤→上阵，遮罩、手指、点击限制、返回路径一致。
4. 战斗：对照第一段 50–68 秒，再对照 82–98 秒；核对站位、技能、伤害字、MVP、奖励、升级顺序。
5. 召唤：第二段单抽与十连，扣资源、获得角色、展示顺序、返回后列表更新一致。
6. 保存：退出重进保持角色、编队、关卡、货币和引导进度；奖励不能重复领取。
7. 画面：在录屏 720×1600 输出下对齐；原代码 720×1280 设计尺寸须验证长屏适配，不能整体强行拉伸。按页面、动画、音频、操作、状态分别记录通过/差异/未知。
