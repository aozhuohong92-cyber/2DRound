# 《航海冒险》安装包反编译分析

本次已完成 APK 解包、Android Java 反编译、全部 Lua 文件解码、批量 Lua 反编译、语法检查、部分资源路径恢复及复刻计划。**这是一套可阅读、可继续恢复的客户端材料，不是已经可以重新编译、联网运营的完整游戏工程。**

## 结论与成果

| 项目 | 实际结果 |

| 脚本模块路径 | 已恢复 1,808 个可读脚本路径，另有模块名/哈希索引 |

| 验证范围 | 静态分析、字节码加载、源码语法检查；没有运行游戏、登录账号或验证玩法等价性 |

“语法检查通过”只证明文本可以被 LuaJIT 编译。反编译可能丢失变量名、局部作用域或复杂控制流，不能因此断言每个函数与原程序行为完全相同。部分代码已经出现可疑的 `slot`/`uv` 引用与条件表达式，必须结合字节码和实际运行核对。

## 代码在哪里

- `lua-decompiled/`：按哈希文件名保存的主交付 Lua；2,136 个，全部通过语法检查。
- `lua-restored-paths/`：已验证名称映射的模块目录，含 `main.lua`、`config.lua`、`file_update.lua`、网络元数据及大量玩法模块。原包中的随机命名空间保留，不擅自假装成原开发目录。
- `lua-bytecode/`：全部 2,146 个解码后的原始字节码，是核对逻辑的重要依据。
- `lua-partial/`：未完整恢复文件的尽力输出，可能包含缺失块、占位表达式，不能直接用于产品。
- `lua-disassembly/*.luajit.txt`：待恢复文件的完整 LuaJIT 指令转储；同目录普通 `.txt` 是 LJD 的辅助输出，可能只输出了部分流程。
- `android-decompiled/sources/`：Java 代码。
- `android-resources/resources/`：可读 Manifest 与 Android XML 资源。
- `apk-extracted/`：完整原包内容，包括素材、原始 DEX 和 `.so`。
- `native-analysis/`：原生证据与关键函数汇编；`recovery-tools/`：本次重建的解码工具与修正过的 LJD。
- `recovery-status.json`：以每个 Lua 文件为单位的最终状态。`lua-decompile-status.json` 等带 retry 的文件是中间过程记录，应以最终状态为准。

代码入口和主要模块可从《代码索引.md》浏览。所有路径恢复都经过包内哈希匹配，不是仅根据类名随意重命名。

## 已确认的客户端结构

启动链：GameSdkActivity → Cocos2d-x AppDelegate → `main.lua` → config/cocos 初始化 → `file_update` → 后续模块装载。

业务层包含角色、英雄养成、背包、战斗、主界面、关卡、登录、任务及多种活动。索引中有 114 个不同控制器名称；协议注册调用共 1,516 条，去重后涉及 1,333 个数字 ID。这些是静态扫描结果，不代表所有模块都会在当前区服开放。

同名 HeroModel、HeroController、LoginController 等存在多个变体。必须依据启动路径、模块加载表和更新后的运行状态确定实际使用版本，不能把所有同名文件随意拼在一起。

## 如何达到“一模一样”

先复现 720×1280 竖屏下的核心画面和单场战斗，再逐模块补齐。使用已提取的 CSB、Spine、贴图和音频能减少重画成本，但仍要恢复资源路径、原生扩展和业务状态。

APK 没有提供完整原服务端工程。登录、角色数据、奖励、战斗结算等涉及服务端的部分，需要重建自己的服务或用本地模拟数据完成离线样例。录屏用于确认交互、状态、演出、音效和显示数值，不能还原隐藏掉落概率或服务端算法。

本次没有生成新游戏 APK，也没有完成可编译的复刻项目。下一步按《复刻实施计划.md》推进，并用《试玩录屏清单.md》中的前三段视频建立对照基线。
