# 离线客户端实施任务

目标：使用现有 Android 真机，先恢复包内客户端的画面、交互、引导和战斗。以用户录屏为验收依据，服务器暂不建设。

## 当前执行顺序

1. 原生运行验证（前轮已通过）：独立包名 org.local.onepiece.offline，以原包原生库和 Android 桥接类运行可编辑 Lua 入口。首版不申请网络权限，直接进入本地场景。验证包不覆盖原游戏。
2. 原始资源验证：加载一个原始背景、一套 CSB 节点、一名 Spine 角色；保留尺寸与动画事件，记录缺失资源。
3. 基础框架恢复：补 BaseClass、确认模块加载顺序；引入本地状态和存档，区分未经验证的反编译代码与人工重建逻辑。
4. 新手引导闭环：主城→命名→基础召唤→上阵，逐项对照录屏的遮罩与触控限制。
5. 战斗播放闭环：布阵→开战→技能事件→结算→奖励与本地保存。先固定样例战报验证演出，再补战斗规则；不能把样例播放当作完整战斗系统。
6. 扩展：伙伴养成、高级召唤、十连、装备、失败重试，逐项记录差异和所需补录。

## 本轮验收

- APK 能在 vivo V2405A 启动，原游戏包保持安装。
- 日志证明实际进入自定义 Lua 入口。
- 原资源能在原 Cocos2d-x 运行时显示，而非用录像替代程序。
- 保留可重建入口、打包脚本、APK、截图和失败记录。

## 工程边界

这是利用原包运行库的兼容性验证工程，尚不是完整可从 C++ 源码编译的产品工程。Java DEX 与原生 .so 当前复用包内二进制，Lua 新入口可编辑。依赖 outputs/apk-extracted；生成物不能证明全部原生源码或服务端已恢复。
