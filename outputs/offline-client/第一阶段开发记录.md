# 第一阶段：资源与离线基础框架

状态：代码、本地逻辑检查和 APK 构建完成；原生运行效果待集中真机调试。本轮未调用 ADB 或 Mobile MCP。

## 已实现

- `prepare_assets.py` 根据原资源哈希规则解析依赖，从原始目录直接打包，不改写原资源。当前包含背景、路飞 H30104 的待机/攻击/技能/受击/移动五组 Spine、原战斗血条 CSB、字体及相关图集，共 22 个文件。路飞伙伴编号 20510 与模型 H30104 的对应关系来自原 partner_data 的 20510_5 配置。
- `bundle.py` 将自写模块放入 `package.preload`，与入口合并后使用已验证的 main 编码规则封装，避免未经验证的单模块文件名加密与搜索路径问题。
- `src/main.lua` 为资源集成场景，提供五个动作切换按钮、原字体文本、原 CSB 和资源错误日志。不是录屏中的主城或完整战斗。
- `offline.class` 提供手写 BaseClass 兼容子集：父类到子类构造、子类到父类析构、重复析构保护。尚未验证整个原框架，未替换原始反编译文件，也未全局加载其模块。
- `offline.events` 提供监听、注销、分发中变更监听列表及回调错误隔离。
- `offline.codec/store` 使用不执行代码的数据格式、版本和校验和校验、双槽临时文件改名保存。最新槽损坏时恢复上一槽；两个槽均不可读时保护原文件并返回错误。
- `offline.state` 提供名字、角色、队伍、货币、关卡、引导步骤和领取记录的状态结构；保存成功后才提交内存状态并发送事件。测试用命名→固定召唤→上阵→固定奖励可以完成，奖励标识不能重复领取。

## 本地验证

在项目根目录执行：

```sh
python3 outputs/offline-client/verify.py
python3 outputs/offline-client/build.py
python3 outputs/offline-client/verify.py --apk
```

验证覆盖 Lua 语法、10 组核心行为测试、21 组加密/原 C 解码往返、22 个依赖和 6 个 CSB 图片帧、APK 资源 SHA-256 与封装入口一致性。构建执行 zipalign、apksigner 签名及验证。结果见 `local-verification.json`、`build-report.json`、`asset-manifest.json`。
