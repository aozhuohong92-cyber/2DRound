## 音效无声定位与修复（真机）

真机反馈技能无声音，随后确认用户此前听到的是无声版本；黑边已消除、Jet.枪五段可完整播放。排查结论：

- 设备上已安装的 APK 里 5 个 mp3 的 zip 条目是 deflate（compress_type=8）。Android `AssetManager.openFd()` 只接受**未压缩且 4 字节对齐**的资源，因此 `Cocos2dxSound.createSoundIDFromAsset` 抛 `FileNotFoundException: This file can not be opened as a file descriptor; it is probably compressed`，音效无法加载。证据保留在 skill-device-acceptance/process-audio-before-fix.log。
- 原包中全部 428 个 mp3 均为 stored（compress_type=0），与原引擎行为一致。
- 修复：build.py 对音频（mp3/ogg/wav/m4a/aac/caf/wma/flac）统一使用 ZIP_STORED，资源表与 assets 附加目录两条写入路径都覆盖；新增 zipcheck.py 的 assert_audio_uncompressed 作为硬性构建检查，任何音频被压缩或未 4 字节对齐都会让构建失败。verify.py --apk 复用同一检查并输出 audio_uncompressed 计数。

真机复测（同一台 vivo，安装修复后的 APK，触发普攻/Jet.枪/二档）：

- logcat 显示 SoundPool 从 APK 资源 fd 成功加载：`load(fd=185, offset=55501936, length=12610)` 等 4 个文件，offset 与 zipalign 后的对齐偏移一致；`Sample 1..4 loaded`、`play returned 1..5`，并生成 AudioTrack 播放。
- 不再出现 Cocos2dxSound 的 compressed 错误。证据：skill-device-acceptance/logcat-live.log。

结论：音频打包层面的无声原因已修复并真机确认播放链路打通。实际听感（音量、时机）仍需用户主观确认；后四段仍以完成事件兜底的受击时机也仍需继续核对原生事件。


## 受击时机改为跟随原生 hit 事件（真机）

此前后四段受击靠动画完成事件兜底触发，时机不准。核对原始战斗代码后确认正确映射。

出处：`outputs/lua-restored-paths/0zWHhlnBORyiROK6lvI6VBn6vAbJRQqS/battle/new_view/skill_act.lua` 的 `SkillAct.setAnimationWithEvent`（约 986–1075 行，另有 1394 行起的同类副本）。Spine 事件语义：

| 事件名 | 原生行为 |
| --- | --- |
| `hit` / `Hit` / `HIT` | 触发伤害/受击回调，按 `hit_time < hit_num` 计数（默认 hit_num=1） |
| `attack` | 只做 attackPoint（攻击点/停帧）与范围受击，不是伤害回调用点 |
| `hit_numN` | 设置连击段数 hit_num |
| `ready` | attackReady |
| `shake_point` | playShakeScreen(shake_id) 震屏 |
| `move` / `back` | moveTo / moveBack |
| `hit_none` / `hit_big` | actHurt（无伤害/大受击） |

据此把 skill_player.lua 的触发条件从 `attack` 改为 `hit`（大小写不敏感），保留仅在没有 hit 事件时才使用的 `completion-fallback`，且仍按来源分别记录，便于区分是否真正对齐。

真机复测（修复后 APK）：普攻、Jet.枪五段、二档全部 `SKILL_HIT ... spine-event`，三段运行中 completion-fallback 计数为 0。Jet.枪每段的 hit 都紧随该段自身 `hit` 事件（action1 在 attack 之后的 hit 处触发）。证据：skill-device-acceptance/normal.log、jet.log、gear2.log。tests/test_skills.lua 同步改为断言 hit 来源为 spine-event，并覆盖大写 Hit 与 attack 不触发。

遗留：`hit_numN` 连击段数在反编译里存在 slot/uv 混淆（赋值来源可疑），当前三个技能均无该事件，暂未实现，待后续用带 hit_numN 的原技能资源核对后再补。
